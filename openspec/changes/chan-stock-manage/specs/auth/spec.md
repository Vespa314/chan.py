## Purpose

提供多用户认证与 RBAC 权限控制能力：登录认证、菜单权限与按钮权限控制、用户与角色管理、admin 绝对权限。

## ADDED Requirements

### Requirement: 用户认证
系统 SHALL 提供用户名密码登录并签发会话令牌，未认证用户不得访问受保护资源。

#### Scenario: 登录与登出
- **WHEN** 用户以正确凭据登录
- **THEN** 返回会话令牌并可访问其有权限的资源
- **WHEN** 凭据错误或未登录访问受保护资源
- **THEN** 拒绝访问

### Requirement: 用户与角色管理
系统 SHALL 支持管理员对用户进行增删改查、分配角色、启用停用，以及对角色进行增删改查。

#### Scenario: 管理用户与角色
- **WHEN** 管理员创建用户并分配角色
- **THEN** 用户按所分配角色获得对应权限
- **WHEN** 管理员停用用户
- **THEN** 该用户无法登录

### Requirement: 菜单权限控制
系统 SHALL 依据用户权限控制可见菜单，无权限的菜单隐藏且其路由拒绝访问。

#### Scenario: 菜单可见性
- **WHEN** 用户无某菜单权限
- **THEN** 该菜单对用户隐藏，直接访问对应路由被拒绝

### Requirement: 管理权限控制
系统 SHALL 依据用户是否具备管理权限控制管理类按钮的可见与可用，业务操作按钮对登录用户全部开放，后端对无管理权限的管理操作拒绝执行。

#### Scenario: 管理权限校验
- **WHEN** 用户无管理权限
- **THEN** 管理类按钮隐藏，直接调用管理接口返回无权限
- **WHEN** 用户执行业务操作（查询/加入自选/加入监控等）
- **THEN** 无需额外授权即可执行

### Requirement: admin 绝对权限
系统 SHALL 内置 admin 角色，admin 拥有全部菜单与按钮权限，且不可被删除或降权。

#### Scenario: admin 放行
- **WHEN** admin 访问任意功能
- **THEN** 全部放行，无需逐项授权
